# AskDB Agent

A small desktop app that lets a user connect a local or private database
to their deployed AskDB backend without opening any inbound ports.

## How it fits together

1. User fills in Host / Port / Username / Password / Database in this app.
2. They paste a **pairing code** generated by the AskDB web app.
3. This app opens an *outbound* WebSocket to your cloud backend and stays
   connected in the background.
4. When someone asks a question in the AskDB chat, the cloud backend sends
   the generated SQL down this WebSocket. This app runs it locally
   (reusing the same validate/execute logic as the main backend) and sends
   results back.

The database password never leaves the user's machine — only the
pairing token and query traffic go over the wire.

## Before building

Edit `tunnel.py` and set `BACKEND_WS_URL` to your real deployed
WebSocket endpoint, e.g.:

```python
BACKEND_WS_URL = "wss://api.yourdomain.com/agent/connect"
```

You'll also need the backend-side pieces from the architecture discussion:
an `/agent/connect` WebSocket endpoint, a pairing-token issuance endpoint,
and a request/response correlation registry (`AgentConnection` class) so
`/query` can await a reply that arrives asynchronously over the socket.

## Building the binary

```bash
chmod +x build.sh
./build.sh
```

This must be run **separately on each target OS** — PyInstaller builds a
native binary for whatever OS it runs on, it does not cross-compile.
So: build on a Windows machine (or CI runner) for the `.exe`, on macOS for
the `.app`, on Linux for the AppImage/ELF binary. GitHub Actions with a
matrix of `windows-latest` / `macos-latest` / `ubuntu-latest` runners is
the standard way to automate all three from one commit.

Output lands in `dist/AskDB-Agent` (or `dist/AskDB-Agent.exe` on Windows).

## Distributing it

- Host the built binaries somewhere download-able (GitHub Releases, S3,
  your own site) — one link per OS.
- On macOS, unsigned binaries trigger Gatekeeper warnings; you'll want an
  Apple Developer ID to codesign + notarize before wide distribution.
- On Windows, unsigned .exe files trigger SmartScreen warnings; a code
  signing certificate removes that.
- These signing steps aren't required to test the flow yourself, but
  expect to add them before asking real users to run the binary.

## Files

- `main.py` — Tkinter GUI, entry point
- `db.py` — schema inspection, SQL validation, query execution (mirrors
  the main backend's `schema_inspector.py` / `validator.py` / `executor.py`)
- `tunnel.py` — background-thread WebSocket client with auto-reconnect
- `build.sh` — PyInstaller build script
